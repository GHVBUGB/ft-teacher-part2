# FT Part 1 与 Part 2 接口清单

核对日期：2026-09-23。此清单区分公共 mock、Part 2 本地 Live 候选、旧评测试点与尚未收到的 Part 1 接口。**相同 URL 不表示相同返回结构或已在公网接通。**

| 接口 | 当前状态 | 请求和返回要点 | 合并时要确定 |
|---|---|---|---|
| `GET /api/v1/me` | 公共 mock 与 Part 2 Live 均有 | mock 返回 `id/external_teacher_id/display_name/locale/timezone`；Live 返回 `id/external_id/email/is_test_account` | 统一登录身份与返回字段；Live 需适配公共契约。 |
| `GET /api/v1/enrollments` | 公共 mock 与 Part 2 Live 均有 | mock 返回 `id/teacher_id/course_version_id/run_no/lifecycle_state`；Live 返回 `id/content_version/started_at/completed_at` | 同一个教师与分配 ID；建立课程版本映射；只返回本人记录。 |
| `GET /api/v1/enrollments/{id}/course` | 仅公共 mock 有 | 返回课程、课程版本、两个模块的 `part_key/path` | Live 后端缺此接口；合并前定权威课程配置与模块入口。 |
| `GET /api/v1/enrollments/{id}/progress` | 公共 mock 与 Part 2 Live 均有 | mock 返回 `enrollment_id/course_version_id/parts[]`；Live 返回 `enrollment/rounds` | 需要服务端汇总 Part 1 和 Part 2 状态，冻结 `parts[]` 结构与 `revision` 语义。 |
| `POST /api/v1/auth/password` | Part 2 本地 Live 候选 | `email/password` → `authenticated`、安全 Cookie | 是否沿用公司统一登录，白名单账号仅限测试。 |
| `POST /api/v1/auth/email`、`POST /api/v1/auth/verify`、`POST /api/v1/auth/logout` | Part 2 本地 Live 候选 | 邮箱验证码挑战、建立/撤销 Cookie；发信服务未完成真实投递验收 | 一套登录和账号权限；发送限流、验证码有效期、跨模块会话。 |
| `POST /api/v1/enrollments/{id}/stages/{stage}/round` | Part 2 本地 Live 候选 | `stage=word/sentence/grammar`，返回/恢复本人轮次 | 公共入口只传已核实的 `enrollment_id`；轮次仍属 Part 2 私有。 |
| `POST /api/v1/grammar/rounds/{id}/answers` | Part 2 本地 Live 候选 | `client_submission_id/question_id/selected_option/active_duration_ms`；返回判定和轮次 | 接口不能提前泄露正确答案；重复请求按提交 ID 去重。 |
| `POST /api/v1/speech/rounds/{id}/assessments` | Part 2 本地 Live 候选 | `client_submission_id/question_id/audio/active_duration_ms`；返回状态、分数和有效维度 | 供应商密钥只在后端；未知评分结果不得自动重调或补分。 |
| `POST /api/v1/feedback` | Part 2 本地 Live 候选 | `enrollment_id/client_submission_id/page_path/content` | 明确反馈归属、查看权限及后续处理。 |
| `GET /api/v1/health` | Part 2 本地 Live 候选 | 返回数据库连接和迁移版本 | 只证明该服务当时健康，不证明业务接口联调通过。 |
| `POST /api/speechsuper/assess`、Speechace 试点接口 | 旧演示/本地试点 | 使用 `kind/text/audio` 等试点评测字段 | 不能当作正式教师成绩接口；正式端应使用受保护的轮次和归属校验。 |
| Part 1 Orientation/知识库问答接口 | **未收到实际代码或契约** | Part 1 PRD 要求批准资料问答、知识检查、人工升级、记录出处版本 | 对方给实际路径、鉴权、请求/响应样例、无答案处理、资料版本与来源 ID；不把建议路径写成现有 API。 |
| 公司系统身份、进度接收与 My Page 预约接口 | **未收到正式契约** | 公司教师编号、本次分配、结果事件和业务回执；预约只在满足条件后进入 | 接收方提供测试地址、认证、幂等与独立回读；双方确认谁负责发消息和重试。 |

公共成功格式目前定义为 `{data, request_id}`；错误格式为 `{error:{code,message,retryable},request_id}`。公共 `contracts/openapi.json` 只含四个 mock 读取接口，**不覆盖** Part 2 Live 后端全部路由。合并时要生成一份与最终运行后端一致的 OpenAPI、无真实个人信息的请求/响应样例，以及两部分共用的错误码表。

来源：`contracts/openapi.json`、`server/main.py`、`server/common/schemas.py`、`server/production/app.py`、`server/production/README.md`、`server/practice/speechsuper.py`；Part 1 PRD 和项目上级公共技术约定。公网 Sites 目前只有演示前端，未验证上述 Live API 在公网运行。
