# FT Part 1 与 Part 2 共同身份和字段表

核对日期：2026-09-23。用途：把 Orientation（Part 1）和发音、语法练习（Part 2）接入同一教师端。此表依据现有公共 mock 契约、Part 2 本地 Live 后端及 Part 1 PRD 整理；**未核对 Part 1 实际代码和数据库**。`拟统一`是对接目标，不表示双方均已实现。

## 字段格式

公共 JSON 使用 `snake_case`；内部主键使用 UUID 字符串；公司教师编号使用字符串并保留前导零；时间使用 ISO 8601 带时区格式；时长字段以 `_ms` 结尾；未知分数用 `null`。页面展示的 T001 等短编号只供人查看，不参与身份鉴权和跨系统关联。

| 对象 | 公共字段 | 类型或取值 | Part 2 当前来源 | 对 Part 1 的对接要求与状态 |
|---|---|---|---|---|
| 教师 | `id`（接口中的教师内部 ID） | UUID | mock `Teacher.id`；Live `ft_training.teachers.id` | 两部分使用同一权威教师映射。Part 1 实际 ID 未收到，待核对。 |
| 教师 | `external_teacher_id` | string，唯一 | mock 同名；Live 数据库/API 为 `external_id` | 确认公司稳定教师编号的来源；Live `external_id` 须映射到公共名，不用邮箱或姓名充当 ID。 |
| 教师 | `display_name`、`locale`、`timezone` | string | mock 有；Live `GET /me` 尚未返回 | 确认姓名、语言、时区的权威来源与可见范围。 |
| 教师认证 | `email`、`active`、`is_test_account` | string、boolean、boolean | Live `teachers` 表及 `GET /me` | 登录和测试标记由认证服务管理；邮箱属于个人信息，不作为公共培训任务键；Part 1 不另建独立真实登录。 |
| 课程 | `course.id`、`code`、`title` | UUID、string、string | 公共 mock `CourseResponse`；Live 未提供课程读取接口 | 确定共同课程目录与 Owner，保持一个课程入口。 |
| 课程版本 | `course_version_id`、`version` | UUID、string | 公共 mock 有；Live 题库和规则用文本 `content_version` | 明确 `course_version_id ↔ content_version` 映射。不能直接把文本版本号当 UUID。 |
| 培训分配 | `enrollment_id`（分配对象的 `id`）、`teacher_id` | UUID、UUID | 公共 mock 和 Live `enrollments` 均有 | Part 1/2 共用同一 `enrollment_id`；后端每次读取都校验归属。 |
| 培训分配 | `course_version_id`、`run_no`、`lifecycle_state` | UUID、≥1 整数、状态枚举 | 公共 mock 有；Live 现为 `content_version`，缺 `run_no/lifecycle_state` | 需要公共服务确定这三个字段的来源、重新分配规则和生命周期枚举。 |
| 模块进度 | `part_key` | `orientation` 或 `practice` | 公共 mock 已定义 | Part 1 写 `orientation`，Part 2 写 `practice`；不得为每个子关卡造新的公共 part_key。 |
| 模块进度 | `completion_state` | `not_started/in_progress/completed` | 公共 mock 已定义；Live `/progress` 目前返回轮次，未汇总此字段 | 两部分分别根据自身证据更新，完成学习与考核通过分开。 |
| 模块进度 | `assessment_state` | `not_evaluated/passed/failed/needs_review` | 公共 mock 已定义；Live 未按此结构返回 | Part 1 PRD 的 `Ready/Needs Review/Not Ready/Incomplete/Escalated` 是 Orientation 业务结论，不可自动等同于公共 `assessment_state`；映射需双方及业务确认。 |
| 模块进度 | `can_enter`、`progress_percent` | boolean、0–100 或 null | 公共 mock 已定义 | 由后端决定入口；无可靠进度算法时填 null。 |
| 模块进度 | `revision`、`summary_version`、`summary` | 非负整数、正整数、对象 | 公共 mock 已定义；Live 尚无公共汇总 | 防旧结果覆盖新结果；摘要只放公共界面所需内容，逐题分数、原始对话和供应商返回仍在模块内部。 |
| Part 1 私有记录 | `orientation_outcome`、`knowledge_check_results`、`content_version`、`escalation_status` | 具体格式待 Part 1 提供 | Part 1 PRD 只描述需求，未见实际表/API | 由 Part 1 提供实现、状态含义与已批准内容版本；公共层只读取必要摘要。 |
| Part 2 私有记录 | `round_id`、`question_id`、`client_submission_id`、`score`、`active_duration_ms` | UUID、string、UUID、0–100 或 null、毫秒 | Live 后端与 `ft_training` | 由 Part 2 保管轮次/逐题证据；`client_submission_id` 用于去重；`active_duration_ms` 是客户端报告的有效答题时间。 |
| 结果同步 | `event_id`、`enrollment_id`、`part_key`、`revision`、`occurred_at` | UUID、UUID、枚举、整数、时间 | 2026-09-17 对接清单提出，当前未见已接通的回传 API | 双方确认接收方、幂等键、回执和对账；不能仅凭 HTTP 成功认定结果已落库。 |

## 统一边界

公共数据库只保留教师、课程、培训分配和两部分进度的权威记录。Part 1 知识库、问答和教学内容以及 Part 2 题库、评分和录音由各模块持有；如需共享文件，只交换受控的 `asset_id` 或访问接口。原始录音、会话密钥和真实教师资料不放在 Git 仓库。

依据：`server/common/schemas.py`、`contracts/openapi.json`、`server/production/app.py`、`server/production/migrations/001_initial.sql` 至 `009_runtime_limits.sql`；项目上级 `02_FT培训客户端_技术栈与开发协作约定.md`；Part 1 PRD `AI_Free_Trial_Teacher_Orientation_Trainer_PRD (1).docx`（需求文件，不是接口实现）。
